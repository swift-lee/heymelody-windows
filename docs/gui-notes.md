## 界面与现有功能

主界面保持 `FAAppWindow` 和 FluentAvalonia 主题，窗体请求普通 Mica，底部设备栏背景透明，上方页面保留不透明背景；Mica 不可用时回退主题实色。设备卡片与“+”在圆角区域内有 `ControlSolidFillColorDefaultBrush` 实色底板，叠加原有选中、悬停和按下状态颜色。均衡器内动态低音移除额外直角异色背景。低音强度和提示音音量使用底部刻度、原有整数档位吸附，右侧显示当前档位整数；范围来自当前设备和所选配置来源，不添加未经定义的单位。黄金听感测试音量保留原有刻度及下方档位、播放确认和重试提示。

## 交互约束

- 选项使用原始协议编号，不以列表下标代替。降噪主按钮点击提交父模式，子档选择提交子档；已回读确认的相同目标不重复写入，父态回读不会自动选中首个子档。模式及细分控件在请求处理期间保持可操作，串行通道仅保留用户最后一个待提交目标，前次明确成功后重新校验设备、连接代次、来源和能力再提交。失败、缺失回执、超时或生命周期变化清除延后目标；旧回读不覆盖较新的选择。旧 Host 未提供主模式能力时禁用主按钮。声音预设与空间音频沿各自控件提交；开关仅由用户点击提交。
- 声音、设备、BassWave 等动态设置行以及 EQ 预设和自定义 EQ 条目同样不因写入待确认而禁用。设置行在同一提交组忙碌时把用户目标排队：同一行只保留最后一次修改，不同行按点击顺序一次一项；排队行重建后仍显示排队值。EQ 预设与自定义条目共用一个“最后点击”槽位，显示随最新点击，条目选择在未观察到前由 `PendingEqEntryId` 标示。前一项明确确认后，重新校验设备、连接代次、资源版本和能力，当前回读已满足目标则跳过写入；失败、不确定、超时、取消或生命周期变化会丢弃所有排队目标并重新显示耳机观察值，不重试也不重放。保存自定义 EQ 仍是显式命令，其后到达的 EQ 点击在其确认后才发送。通知和缓存回填不触发写入。
- 同一耳机的命令串行，不同耳机使用独立 worker；界面编辑独立进行。界面接收后台订阅的单调 revision 状态；初始化、重新连接、手动刷新及设置前后验证仍执行 GET，普通状态更新由蓝牙通知推动。`IsRefreshing` 只表示读取活动；`Busy` 表示连接等生命周期操作或待执行的用户提交，不作为统一禁用条件。除降噪选择外，提交期间禁用同组的提交按钮或开关；下拉选项、EQ 名称和滑块仍可编辑，其他组仍可提交。空间音频与 Hi-Res 共用一组，预设和自定义 EQ 共用一组；每组最多保留一个执行中的提交，降噪另保留一个尚未开始的最新用户目标。应用设置在读取和写入期间仍可打开。
- 写入要求快照 ControlReady、型号和能力均已核验，后台实例、设备身份及连接代次与冻结目标一致。BLE 可补充新鲜电量，后台记录盒盖/佩戴状态并发布开盖事件；现有界面不单独展示盒盖/佩戴状态，设置权限仍由 RFCOMM 实际核验。读取失败的状态保持未知，相关写入禁用。状态推送和刷新不提交设置；不持续强制执行已结束的用户目标。下拉框按协议编号保留待选值，EQ 按条目与编辑版本保留本地调整；相同内容的列表不会反复替换。提交使用冻结的设置，回读不会覆盖提交后继续编辑的内容。
- “保存均衡器”执行保存并选用；“启用此 EQ”只选用已有且无未保存调整的条目。切换条目、切换或断开耳机、新建、刷新可能改变连接的设备列表及关闭窗口，会先确认丢弃草稿。取消这些草稿丢弃或关闭确认会保留草稿；普通状态刷新不会询问丢弃草稿。
- 游戏音效开关与类型每次操作最多提交一次，明确失败只提醒一次，未知响应只读核对，不弹出再次写入确认。失败、取消或无效提交后，复用控件恢复耳机观察值，其他草稿与较新的编辑仍保留。除降噪外，其他用户目标最多执行两次逻辑尝试：收到完整后台回执、连接及同一设备身份可核实的绝对值设置失败时，等待 500 ms 并重新读取；目标已达到则结束，仍未达到且安全才自动重试一次。需要再次创建 EQ、状态或能力不足以安全自动继续时，使用 `FAContentDialog` 询问“确认 / 取消”，默认取消。确认后再次读取和校验；确认本身不能绕过身份、连接或能力检查。后端每次尝试均重新核对能力和状态，不在传输层重放 SET。手机改变设置不会单独触发冲突确认；本次 Windows 提交仍使用冻结的明确目标。
- 取消再次写入确认时，会清空全部待选设置、EQ 草稿与尚未开始的写入，然后立即完整刷新。该行为不适用于普通草稿丢弃或关闭确认。第二次失败只弹出“确定”提醒；关闭提醒后立即完整刷新，不再重试。明确断连、控制连接状态未知或未取得完整后台结果时，第一次就提醒，关闭提醒后只读刷新，不自动重发。最终刷新失败只更新状态提示，不再次打开同一操作的对话框。设置、重试、失败与应用设置对话框共用协调器。
- 空间音频与 Hi-Res 各自提交目标，不弹出关闭另一项的互斥确认、不提交前置关闭操作；两项均显示耳机实际读回值。`AllowMutexChange` 与 `SpatialHiResMutex` 字段保留接口兼容。新建 EQ 失败后，先核对不在原列表中的唯一同内容条目：已选中则结束，未选中则复用该 ID；有歧义或重名时不再次创建。后续保存使用已核实的 ID，避免创建重复条目。
- ACK 接受与当前目标已回读到是两项独立事实。未知或拒绝的响应不会因匹配回读而改成成功响应；失败及未知响应提示不会被普通状态推送清除。同版本的待选值在目标已观察到后解除保护，后续手机端修改可正常显示；提交期间的新编辑仍保留。
- 应用设置不会与正在执行的控制确认重复弹出。关闭先停止接收新操作并取消尚未开始的写入，收起设置框和当前控制确认，再处理草稿确认；取消关闭会保留草稿并恢复窗口操作。确认关闭后解除事件订阅并断开界面管道连接，再结束主界面进程；已经开始的后台设置继续完成 ACK 和回读。
- 界面中的操作日志在当前进程保留最近 80 项，继续遮蔽设备标识、MAC 与设备路径。应用设置另提供一次后台周期的 Debug 诊断日志，包含完整协议与异常；组件选择、目录和启停边界见[诊断日志](diagnostics.md)。

“连接或同一设备身份无法核实”包括：后台进程崩溃、超时或返回损坏/不匹配的 RPC 记录，导致客户端没有完整回执；重新读取时无法取得有效型号、能力或连接状态；返回的设备身份与当前选择/连接会话不一致；后台重启后丢失原地址到随机身份的映射。此时设置可能已经到达耳机，不能把旧请求转移到另一副同名耳机。程序提示并只读刷新，身份映射丢失时要求重新选择并连接。手机修改某个设置本身不属于身份无法核实，也不能仅凭一次 GET 超时断言蓝牙已断开。

## 平滑滚动

主窗口设置区 `ControlScroll`、底部设备栏 `DeviceBarScroll`、设备管理器 `DeviceScroll` 和校准向导 `PageScroll` 使用 SmoothScroll.Avalonia 12.0.0.14 的局部滚动主题，输入子包固定为仓库携带的 `SmoothScroll.Avalonia.Interaction 12.0.0.15-heymelody.2`。设备栏的整数与小数纵向输入都交由库映射为横向滚动，嵌套列表等控件保留原有 FluentAvalonia 模板。启用平滑主题时，滚动到目标（`BringIntoView`）使用 500 ms 动画；启动时若系统关闭动画，则保留原主题及即时滚动。许可原文见 [SmoothScroll.Avalonia MIT 许可](licenses/SmoothScroll.Avalonia-LICENSE.txt)，局部补丁、来源与手动重建见 [vendor 说明](../vendor/smooth-scroll/README.md)。

触摸板小数输入在一段连续操纵中处理，包含期间的整数包；静默 80 ms 后按库的末端速度估计衔接惯性和回弹。低于 50 DIP/s 的尾速不再追加惯性，与最后实际输入方向相反的拟合速度也会舍弃，避免把衰减尾包重新抬速或反向甩动。每轴回弹上限按输入时的视口计算，为其 12% 且不超过 96 DIP，同时限制原始超程及惯性撞边后的模型，避免整页飞离或反向时耗尽隐藏距离。滚轮事件没有可靠的手指离开阶段，静默窗口是兼容策略，不能据此宣称识别所有硬件的系统惯性阶段。点击、键盘、显式定位与卸载会结束该段操纵。

触摸或笔从设置分组标题开始时，仅在属于当前滚动页的 FluentAvalonia 标题 ToggleButton 路径上放行已处理的按下、移动和释放事件，让库按原拖动阈值接管滚动；轻触展开仍由原按钮处理。标题 Footer 区域（含其编辑器）与嵌套滚动页保留自己的输入处理，鼠标和键盘不走该转接。触屏及笔沿用库原有的拖动路径。定向检查使用模拟输入；触屏标题修复已有用户实机反馈，但本轮触摸板参数未作物理硬件验证，也未覆盖 Pen 模拟或 ARM64 硬件。

上游将此库标为实验性。本轮固定在 Avalonia 12.1.4／FluentAvalonia 3.1.0 验证，后续升级需复核组合渲染、滚动定位与卸载行为；原始包、源码版本和接入记录保存在本地 `research/smooth-scroll-review/20261024-package/`。

## 字体与字符渲染

界面只支持简体中文。0.9.0 之前没有配置字体：默认字体族为 Segoe UI，汉字靠回退匹配，而 Avalonia 的回退按文本区域性（为空时取界面区域性）给字体打分，英文 Windows 上可能选到日文字体，同一汉字显示日本字形。现在各界面进程把界面区域性设为 zh-CN（不改变数字和日期格式），默认字体为系统 Microsoft YaHei UI（西文与数字也由它显示，中英混排行高一致），并用 `FontManagerOptions.FontFallbacks` 把汉字、CJK 标点和全角字符固定回退到同一字体，先于任何按区域的打分。雅黑只有细体、常规、粗体，550–699 字重（如 SemiBold 标题）映射到真实粗体字面，不合成加粗。没有雅黑的系统使用随包 `fonts/` 中的 Noto Sans SC（常规、中等、粗体，OFL-1.1）。

窗口显式设置完整 hinting（经 DirectWrite 使用雅黑的手工微调）与像素对齐基线；抗锯齿方式由 Avalonia 决定：不透明表面使用子像素，图层与 Mica 透明区域改用灰度以免彩边。中文最小字号 12 px。托盘菜单由 Avalonia 绘制，同样使用这些设置；托盘提示文字与任务栏标题由 Windows 绘制，英文系统上仍按系统字体链显示。实现在 `src/HeyMelody.App/Typography.cs`；本轮在 Linux 无头环境验证英文区域下的匹配结果，en-US Windows 的实际观感仍需在 Windows 上目视确认（可检查“直、骨、角、写、画”）。
