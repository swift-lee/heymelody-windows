# 欢律单源与升级兼容

当前开发分支仅使用欢律 App 的设备配置与美术，不再提供 ColorOS“无线耳机”来源、来源切换或跨来源补全。Avalonia 与 FluentAvalonia 界面继续沿用现有设置卡片、开关、密钥输入和重新下载功能。产品版本仍为 0.9.2，本轮未发布安装包。

## 配置与控制

预装欢律 17.6.5 对应目录包含 85 个展开产品 ID。旧双来源目录中另外 56 个耳机 ID 仅属于已退出支持的来源，不能再获得控制权限；系统配对和设备身份不因此删除。目录覆盖不等于真机验证。

请求使用欢律渠道 2 和兼容标记 17006004，保留原有内置／云端整份配置择优、认证、下载完整性检查及失败回退。控制权限仍由欢律配置、App 条件、已实现的 codec 和设备能力共同决定；固件条件仅产生提醒。图片、名称、广播和缓存不授予控制权限，通知及状态回填不触发 SET。

## 本地升级

- 首选项仅保存一个 `HeyMelodyKey`。旧文件的来源和另一来源密钥被忽略，原欢律密钥、在线开关及有效缓存加密密钥保留；欢律缓存继续位于 `resources/online/heymelody`，历史另一来源缓存不加载、不迁入，也不主动删除用户磁盘上的原件。
- `device-state.json` 升至 schema 2，去掉来源字段。schema 1 仅迁移明确标记为欢律的展示条目及首选设备键，随后原子写入新文件。展示缓存始终只读，不恢复会话、连接代次、观测或写权限。
- 外观观测、Windows 配对及无来源字段的听感历史保留，是否可用仍按当前欢律配置和设备能力判定。
- 公共 IPC 升至 schema 4，沿用原用户会话管道及后台互斥锁。新旧端不混用；更新时退出旧托盘后台，再打开完整的新客户端。

## 资源与界面

当前美术索引保留 365 条欢律记录及 634 个依赖文件，另以补充清单登记一个已核实来自欢律的扫描 PNG。删除另一来源的 478 条记录及 480 个独占文件，保留欢律可达的共享图片、模型和动画。官方黄金听感 module 2 试听同样由欢律调用，继续保留。

界面移除来源选择和双密钥草稿；保存在线开关或密钥不丢弃未保存 EQ。顶部电量区域的左耳、右耳和耳机仓标识使用已核实来自欢律 17.6.5 的矢量形状，详见[电量图标来源](battery-device-icons.md)。应用自绘文字统一使用随包的标准 MiSans 静态字体；通用图标使用固定版本的 Fluent System Icons SVG，欢律资源和项目原创电池几何保持原样。系统绘制的原生菜单、窗口装饰及对话框不重绘。底部设备切换栏仍使用通用 Fluent 耳机图标，按型号展示弹窗本体图片尚未启用。校准继续使用欢律指引，保留右耳镜像及步骤动画。

资源生成和当前采集工具仅处理欢律。发布校验对照当前规范清单检查数量、路径、字节长度、SHA256、Lottie 依赖和补充资产，不再使用旧双来源数量门槛。普通构建仍不依赖 APK 或本地研究目录。

## 依据与验证边界

配置、资源来源和历史获取语义依据[云配置研究](cloud-device-configuration.md)、[云美术研究](cloud-device-artwork.md)及现存资源索引；旧来源相关表格、日期和摘要仅描述当时的研究样本。

本轮改写前原稿及摘要位于本地 `research/migrations/drop-coloros-2026-10-18/`，不随普通 clone 提供。七份已跟踪静态契约不变。固定旧样本的复核通过 [historical_replay.py](../../tools/research/historical_replay.py) 加载已保全版本，仅用于离线历史证据复核，缺少归档时明确失败。

验证使用 .NET 10 的离线、模拟与原生窗口检查。UI 审计限于资源设置区、主窗口受影响的图标及电量、校准图标与步骤；整套截图保留本地，不作完整 UI 审计。验证不操作真实耳机，不证明所有型号、固件或 ARM64 硬件行为。
