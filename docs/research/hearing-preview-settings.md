## 结果雷达

欢律 `Ic.C0470e0`、`Ae.a.M` 和结果页 `Ic.ViewOnClickListenerC0492p0` 共同确定计算与轴位。六个频点按数据顺序为 80、250、1200、2400、4800、10000 Hz；界面对应左上、左、左下、右下、右、右上。左耳绿色、右耳蓝色，橙色表示增强试听的音乐频谱。

曲线来自本次测听与耳道扫描的滤波响应。每段六系数按前三项 P、后三项 Q 分组，累加 `20 log10(|Q| / |P|)`，使用原厂的逆向响应。测听滤波按 44100 Hz 求值；耳道扫描使用返回的有效采样率。原厂频率网格为 `j = round(f × (Fs − 1) / Fs)`，`ω = 2πj / (Fs − 1)`。各点以 `−abs(总响应 dB)` 为增益，尺度依次为 7.5、7.5、12.5、12.5、15、15，半径为 `clamp(10 + 10 × 增益 / 尺度, 2, 10) / 10`。

384 项特殊表示不当作普通 IIR 系数解释；不支持的表示、零分母、非有限值或缺失滤波不会生成虚假曲线。界面提示结果图暂不可用，仍保留协议允许的保存与试听入口。既有 X4 结构 fixture 的系数是合成数据，不作为佩戴者实测听力证据。

客户端通过 Host 快照将已验证的增强频段及描述编号传到结果页，复用引擎已经选定的描述编号，不根据雷达半径、音乐频谱或缓存推断文案。频段仅在滤波完整、唯一主曲线的命令及 UID 匹配且值为 0–2 时提供；未知频段或编号不展示个性介绍。界面以富文本运行段绑定主题强调色，随明暗主题及强调色变化；其余正文沿用普通说明颜色。这些文字沿用 App 的效果介绍，不构成新增声学测量。

## 试听与动画

原厂 `Ic.L` 明确循环播放 `hearing_enhancement_audition.mp3`。0.8.13 内置该资源转出的 48 kHz、双声道 PCM16 WAV，长约 23.066 秒，无需运行时下载或外部编解码器。来源、ZIP/MP3/WAV 大小与 SHA256、转换参数见 [资源来源记录](../../packaging/licenses/Hearing-Audition-SOURCE.json)；维护工具为 [fetch_hearing_audition.ps1](../../tools/research/fetch_hearing_audition.ps1)。

进入结果页不会自动播放。“增强前”“增强后”两个条目使用原生按钮和播放状态；再次点击当前条目暂停，音频循环。播放中切换另一条目时，音乐流持续输出，仅动态改变耳机 DSP 增强参数；切换不暂停播放器、不重启音乐，也不先停止 DSP 预览。两个 APK 的结果页均采用这一分支。增强前与增强后均由实际 PCM 频谱驱动左右耳曲线，增强前隐藏橙色区域，增强后同时显示橙色音乐频谱；暂停后恢复静态左右耳曲线与橙色外圈。没有有效频谱时保留静态结果，不生成模拟音乐帧。

官方动态合成来自欢律 `Ic.C0483l.c` 与无线耳机 `kb.C1242k.c`：`动态半径 = max(2, 音乐半径 + 10 × 增益 / 尺度)`，不是相乘。桌面实现等价使用 `clamp(音乐归一化半径 + 静态耳半径 − 1, 0.2, 1)`。前提是静态耳半径为 `clamp(1 + o, 0.2, 1)`、`o = −abs(响应 dB) / 尺度 ≤ 0`，且音乐半径不超过 1；即便静态结果已触及 0.2 下限，两式仍同样饱和到 0.2，无需从截断值复原真实增益或扩展 IPC。滤波结果对象保持不变，绘制使用派生值；动态曲线是音乐源示意，不是耳机 DSP 输出或实测听力。

播放器位于 Host，使用独立 STA 线程和 WASAPI shared mode，按所选耳机的蓝牙地址匹配唯一的活动 A2DP 输出。它沿拓扑及设备祖先查找 `BTHENUM` 音频服务 `0000110b-0000-1000-8000-00805f9b34fb`，不按名称猜测输出，也不更改系统默认输出或驱动格式。端点准备完成、耳机 DSP 预览命令全部确认后才开始本地播放。保存、取消、断开、切换来源与释放会停止本地音频，蓝牙停止命令失败时仍沿用已有的控制租约保留规则。

WASAPI 的共享模式转换使用 `AUTOCONVERTPCM` 与 `SRC_DEFAULT_QUALITY`；线程要求与参数依据微软的 [IAudioClient.Initialize](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-initialize) 和 [AUDCLNT_STREAMFLAGS](https://learn.microsoft.com/en-us/windows/win32/coreaudio/audclnt-streamflags-xxx) 文档。

频谱使用 1024 点 Hann 窗、48 kHz 单声道均值，六频点取最接近的真实 PCM FFT bin。幅度换算和升降平滑沿用原厂逻辑；Android Visualizer 的采样索引公式不直接套用到桌面 PCM。频谱最高约 20 Hz，独立于控制快照和 revision，worker 使用只保留最新值的通道，管道按 handle 合并，UI 校验 owner、连接 generation、播放 epoch 与序号。频谱更新不会使按钮输入因控制 revision 变化而过期。

## 游戏与 BassWave

已检查的八组配置包括两内置包、两 APK 提取配置及历史两来源的 builtin/cloud 输入。它们包含 EQ 模式的 `order`，未发现声音功能或游戏功能的总体展示顺序；JSON 属性先后也不能视为界面排序声明。因此客户端统一把游戏音效开关放在游戏低延迟附近，适用于两来源、新快照、旧离线缓存、Demo 和预览。

游戏音效类型按用户决定在所有设备上隐藏。现有协议支持及保存值仍保留，游戏开关继续走 `0403 [27, value]`，不因隐藏而写入类型 3。此显示政策依据 X4、X3、Free4 的用户反馈，不宣称已经验证所有配置机型的硬件行为。

BassWave 开关与强度投影到现有均衡器面板，保留原始 feature ID、能力门控及带符号的强度范围。两 APK 中文资源确认标题为“BassWave™动态低音”，说明为“动态增益低音，清晰且高保真地呈现深邃低音效果。”。

## 固件显示

原实现虽然读取 `0105` 的全部条目，但显示只选择 `DeviceType=1 / VersionType=2`，因而只出现左耳的 `137`。欢律 `earphone.Q.z` 与无线耳机 `earphone.L.D` 按左耳、右耳、充电盒拼接运行固件版本。原 DEX 的对应方法也已独立复核：欢律 classes3.dex 的 code offset 为 `0x2e1bc8`，无线耳机 classes2.dex 为 `0x2218f8`。

0.8.13 增加单独的显示版本，完整组件信息可显示 `137.137.105`；硬件版本、备份版本和厂商版本不参与拼接。未知机型类别或已格式化的值保留原值回退。能力判断继续使用原来的单组件版本，避免把显示格式变化引入功能门控。

## 验证范围

2026-10-11（本地日期）完成最终验证：`Build-Client.ps1 -Version 0.8.13 -TestsOnly` 的全部 13 个默认检查程序通过，其中 12 个应用／协议检查程序共 683 项，另有 Windows 离线 ABI／传输检查。Host 的 77 项包含切换期间音频失败、失效播放器重建、停止确认与旧异步任务隔离；连续 A/B 保持同一音乐流，频谱不递增操作版本。

本地 x64 自包含打包和 Python 静态检查通过。ZIP 的 2,843 个文件路径、大小和 SHA256 与发布目录一致，发布 Host 完整内嵌 WAV，两个许可目录均包含音频来源记录。证据入口为本地 [收尾档案](../../research/hearing-preview-20261010/finalization-20261011/README.md)，最终日志位于 `artifacts/release-0.8.13-final-20261011/`，副本与摘要归入研究档案。
