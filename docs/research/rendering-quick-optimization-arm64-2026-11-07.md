# 模型渲染快速优化与 ARM64 复测（2026-11-07）

## 结论与放行范围

接续[首轮性能审计](rendering-performance-arm64-2026-11-07.md)，本轮只修改项目自己的托管配置与中间层：**全平台默认将模型位图长边限制为 800 物理像素，并在直接复制路径确认新帧就绪后才锁定位图**。不修改 Filament、Avalonia、FluentAvalonia，不重编或替换 native 库。

这台 Snapdragon 8cx Gen 3／Adreno 690 设备上，Vulkan 自转／自转加滚动的 CPU 单核当量分别下降约 **19.3%／9.9%**；成功位图复制交付率只提高约 **5.9%／2.1%**。原定“交付率至少提高 10% 且超过基线波动”的放行门槛**没有达到**，Unlimited 测试也不能按被人为帧率上限卡住解释。用户随后明确接受以降低 CPU 开销放行，并要求全平台启用；这是调整验收目标后的决定，不是原门槛通过。

本轮不宣称解决低帧率，也没有测得真实屏幕呈现 FPS。性能与截图证据仅覆盖 Windows ARM64；macOS／Linux 共享托管策略不等于其 GPU、发行库或性能收益已经实机验证。

## 实现与画质取舍

- `ModelRenderPolicy` 先计算控件 DIP × DPI 的物理尺寸，再统一比例缩小、取整并保证至少 1 像素；原尺寸较小时不放大。仅布局／DPI／配置变化时重算，不逐帧自适应。本机 1050×910 → 800×693，输出像素减少约 42%。
- 普通界面、文字和指针坐标仍按原分辨率处理；模型 DIP 布局、相机、FOV、Zoom、FitMargin、旋转速度不变，现有 `Stretch.Fill` 显示缩小位图。
- 保留 MSAA4、FXAA／后处理、材质、曝光、色调映射、透明与背景合成；不修改用户的后端及 30／60／Unlimited 偏好，不恢复焦点／空闲／滚动自动限帧。
- `IFilamentRenderer.TryGetLatestFrameInfo` 复用现有 ABI 2 的 null 指针／零容量查询；只将 `HM_BUFFER_TOO_SMALL` 与合法元数据组合识别为就绪，查询不消费帧、不推进 FrameId。复制路径仍按真正复制结果校验尺寸、代次与 FrameId；只在复制成功并接受后更新呈现状态。
- direct-copy 分支在 `WriteableBitmap.Lock()` 前查询，无新帧立即返回。fallback 本来先取像素后加锁，不重复查询。消除空锁不等于证明每次旧空锁都会触发 GPU 上传。
- 无画质设置页、持久化字段或生产环境测试开关。审计 CLI 的像素上限／查询开关仅覆盖当前测试视图，不写用户偏好。

固定姿态、浅色／深色的原尺寸与 800 像素截图中，布局和模型轮廓一致；800 版本的文字标记、细孔、边缘与高光略软，未见明显裁切、晕边或背景接缝。检查范围为当前测试模型及固定截图，不替代全部模型、真实跨屏 DPI 与手势实机验收，也不证明透明合成数学完全正确。

## 实验口径

Release win-arm64、.NET 10.0.402，真实 Avalonia 测试窗口；固定 1280×900 DIP、1.75 缩放、2240×1575 窗口物理尺寸，同一模型和动画输入、MSAA4、Unlimited。Avalonia 使用硬件合成；Vulkan 为 Mesa Dozen → D3D12，OpenGL 为该机 Microsoft／Mesa → D3D12 路径，不是 WARP。

每轮预热 5 秒、采样 30 秒；Vulkan 自转、自转加滚动各按 B→C→C→B，两轮 B／C 用标准中位数聚合。B 为原分辨率、关闭就绪查询，C 为 800 上限、开启查询。另测只查询 P、只限像素 R；无模型静态滚动、完整生产 WebP 动画及模型冻结；OpenGL 补自转、滚动、冻结；浅／深主题冻结截图。两个深色截图轮次只采样 5 秒，不混入 30 秒性能聚合。

前后电源记录均为 Balanced，电池字段 `BatteryStatus=2`、100%；没有连续监控供电、温度和频率。全部进程顺序运行，采样期间不构建、不连接耳机、不写设备或用户偏好。全平台放行决定之后的最终源码使用共同默认值，实测归档源码当时仍为 Windows 分支启用；两者在本机执行同一策略，原档案不改写。

成功复制 Hz、P95 来自测量完整窗口内实际成功复制事件，和端点计数／FrameId 对齐；不使用 UI callback、native sequence 或近期重叠历史冒充 FPS。CPU 为**单核等价百分比**，此机 8 个逻辑核，换算整机占用需除以 8。P95 是新成功复制事件间隔，包含窗口边界；不是 GPU stage timing。

Vulkan 自转两对复制率分别 +3.953%、+7.985%，基线极差／中位数 3.595%；滚动两对 +2.842%、+1.363%，中位数增幅甚至略小于基线波动 2.147%。两场景 P95 均改善、CPU 两次均同向下降，但不能称为稳定大幅提帧。OpenGL 只有单对，不升级成重复实验结论。

### 单因素

每项只有一个候选轮次，以两轮 B 中位数作参照，不能作为严格因果分解：

| 候选 | 自转复制 Hz／CPU 相对 B | 滚动复制 Hz／CPU 相对 B | 自转／滚动空锁率 |
| --- | --- | --- | --- |
| P：原尺寸＋查询 | −0.963%／−7.377% | +1.024%／−2.690% | 0%／0% |
| R：800 上限、不查询 | +2.537%／−19.508% | +3.571%／−12.826% | 26.657%／7.780% |

查询对应空锁消除，较大的 CPU 节省与像素预算更一致。42% 像素下降不能推导为 42% 提帧或 CPU 降幅；native 持锁合成、整帧 memcpy、读回与上传仍然存在。

### 无模型与冻结

首轮无模型静态图滚动：CPU 63.952% → 62.018%（−3.024%），UI callback 103.290 → 104.777 Hz、P95 16.688 → 16.683 ms；分配 +1.772%、working set 峰值 +0.341%、private 峰值 +0.417%。这些 UI 回调也不是屏显 FPS。

首轮完整 WebP 动画：CPU 23.117% → 24.881%（+7.630%），UI callback 40.520 → 41.442 Hz、P95 33.843 → 33.645 ms；实际动画 draw 30.290 → 30.282 次／秒。private 峰值 268.836 → 296.246 MiB（+10.196%，+27.410 MiB）触发交错复测，不能仅凭这一对宣称内存无回归或确定回归。

随后用同一封存可执行文件与输入，独立完成四轮 B→C→C→B 动画复测。private 峰值中位数 280.523 → 271.664 MiB（−3.158%），working set 峰值 394.533 → 382.172 MiB（−3.133%）；两对 private 变化分别 −9.033%、+3.367%，方向相反，B 自身极差 29.414 MiB，和首轮 +27.410 MiB 同一规模。CPU 中位数 +4.095%、分配 −0.156%、UI callback −2.189%、间隔 P95 +0.269%、动画 draw −0.074%，未见持续超过 10% 的回归。四轮全部前台、健康，240 个进程样本无模型记录、成功模型复制为 0。原单对内存异常没有重复；未进一步定位缓存来源，也不能据此证明长期零回归。

六个冻结轮次的相机、native sequence、成功复制、位图锁、查询计数增量均为 0，未持续制造帧工作。CPU：OpenGL 4.894% → 4.217%，Vulkan 深色 4.983% → 4.671%，Vulkan 浅色 2.707% → 3.906%；最后一项相对变化大但绝对为 +1.199 个单核百分点，不能直接归因模型策略。无模型页面均不创建模型渲染器；本轮没有修复普通界面自身滚动成本。

## 回归与验证边界

托管测试覆盖尺寸、比例、DPI、无效输入、无帧不锁、随后完成、重复 FrameId、查询后复制丢帧／resize／换代恢复、direct／fallback 一致性与销毁，以及原生错误码／元数据契约；保留 30／60／Unlimited 调度、动画、滚动和模型加载验收。

最终全平台默认源码的 Release win-arm64 构建通过；七组验收合计 **397 checks**：渲染策略 21、审计／演示 CLI 36、渲染偏好 3、模型加载／帧循环／复制 105、动画 6、滚动 57、Filament 托管边界与资源契约 169。最后一组不加载 native 库，不能当作 GPU 验收。构建仅有既有未使用事件警告。

最终原生 Vulkan 短测另通过 **78 checks**：不设置审计 override，核实实际生产默认 800／查询开启、就绪查询与成功直接复制、浅深主题及宽窄窗口，窗口正常关闭、偏好未写入、蓝牙调用为 0。它使用已有 native smoke 的 Avalonia platform defaults，不作为生产硬件 compositor 性能测量；性能结论仍来自独立矩阵。比较器另通过 8 个合成自测用例。

Windows 上另用 `HeyMelodyDesktopPlatform=macOS`、独立 artifacts 目录编译通用 TFM／macOS 条件分支，0 错误、0 警告。明确以空目录 glob 排除了本机缺失的 macOS bridge／Filament dylib；这只证明托管代码可编译，不是可运行 macOS 包、Metal 或原生桥接验收。

native ABI 仍为 2；实测及最终输出的 Windows ARM64 库／manifest 身份不变：

- `HeyMelody.Filament.Native.dll` SHA256：`f563f85a2fbc1fbbcc475c94caa0a167ef679ef980711d369d0fbb3e6c01b6aa`
- manifest SHA256：`91761d1c8e470ef1fed3448db773eeaf59450e55631d744931c14667553a6dfa`
- native 来源提交：`ea31afeaf66339e7414aa648aa76c7e61adbde28`，19 文件静态身份核对。

本机没有 macOS／Linux GPU 或可核验的 macOS dylib。共享 native 源码的 null／0 查询分支不区分后端，但不能仅凭 ABI 2 推断任意历史发行库均行为一致。GPU timestamp 在这条 Vulkan 路径不可信，ETW 也未获得可用采样，本轮不作 GPU 阶段归因或屏幕呈现承诺。
